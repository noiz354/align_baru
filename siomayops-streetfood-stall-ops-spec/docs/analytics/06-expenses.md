# Page 06 — Expenses analytics

**Implementation:** `src/features/expenses/analytics.ts` uses the existing structured Pino logger. No competing analytics SDK was introduced.

## Events

| Event | Trigger | Safe properties | Downstream use |
|---|---|---|---|
| `expenses_viewed` | Authorized unfiltered `GET /api/v1/expenses` | `page=expenses`, request ID | Coarse page usage and service diagnosis |
| `expense_filter_changed` | Authorized list request with a supported filter | Page, request ID, filter key (`businessDay`, `stallId`, `category`, `reviewStatus`, `paidFrom`) | Understand filter use without recording the selected value |
| `expense_created` | Successful create use case | Page, request ID, resulting coarse review status | Count successful record creation |
| `expense_create_failed` | Invalid/unauthorized/precondition/server-failed create response | Page, request ID, HTTP status code | Diagnose create friction and failure rates |
| `expense_detail_viewed` | Authorized scoped detail read | Page, request ID, coarse review status | Coarse detail usage |
| `expense_reviewed` | Review boundary completed successfully | Page, request ID, HTTP status code | Count completed review actions |
| `expense_review_failed` | Review idempotency/use-case response failed | Page, request ID, HTTP status code | Diagnose review failures |

`requestId` is generated by the server for correlation. Filter values are deliberately not recorded. Unauthorized list/detail reads return before the product page event is emitted; create failures are logged at the create boundary.

## Prohibited event properties

Do not add expense description, operator note, review reason, evidence/object key or media, amount, client expense ID, employee/operator identity, shift ID, outlet/org ID, phone, auth/session token, or raw request body. Audit events have their separate authorization/audit purpose and are not the product analytics payload.

## Evidence and limitations

Focused API tests observed page, create success/failure, detail, filter, and review events in the existing logger output. A local dev runtime emitted `expenses_viewed`, `expense_created`, `expense_detail_viewed`, and `expense_create_failed` during list/create/read/invalid-input checks. No analytics warehouse/remote ingestion is wired or claimed. See `docs/integration/06-expenses-runtime-evidence.md`.
