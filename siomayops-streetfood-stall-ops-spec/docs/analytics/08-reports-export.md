# Reports & Export analytics contract

**Page:** `/reports`
**Implementation:** `src/features/reports/analytics.ts`
**Logger:** existing structured server logger (`src/server/telemetry/logger.ts`). No second analytics SDK is introduced.

## Event catalogue

| Event name | Trigger | Allowlisted properties | Downstream use |
|---|---|---|---|
| `report_viewed` | A successful authenticated `GET /api/v1/reports` | `page=reports`, request ID, range length in days, optional filter-kind list | Understand report reach and query-window size |
| `report_filter_changed` | A successful report read with at least one supplied date/area/outlet filter | Same safe properties as `report_viewed` | Distinguish filtered use from default-period viewing |
| `report_export_requested` | An authorized request reaches the export filter-validation stage | `page`, request ID, filter-kind list | Count export intent, including invalid filter submissions |
| `report_export_succeeded` | CSV has been generated and export audit persisted | `page`, request ID, status, range length, bounded output row count | Measure successful export usage |
| `report_export_failed` | Export request has no session, fails authorization/validation/read/audit, or exceeds supported bounds | `page`, request ID, status and range length if known | Diagnose failure rates by response status |

Only `dateRange`, `area`, and `outlet` filter categories are emitted; raw filter values are not. The logger does not receive row data or report totals. Request IDs are generated by the server. Status is a stable HTTP code string.

## Prohibited properties

Do not add names, phone numbers, operator/customer identities, organization/outlet/area IDs, raw CSV, sales/expense/payment amounts, incident descriptions, credentials, auth/session tokens, raw filters, or arbitrary error text to report analytics. CSV business data is returned only to the authorized requester and is summarized in the separate append-only audit event without free-text source rows.

## Evidence

API tests assert the event-producing successful read/export paths in test logs and the denial path emits `report_export_failed`; example structured event names include `report_viewed`, `report_filter_changed`, `report_export_requested`, `report_export_succeeded`, and `report_export_failed`. Runtime command/output details are in `docs/integration/08-reports-export-runtime-evidence.md`. The event implementation is a structured log abstraction; no external analytics transport or durable event warehouse is claimed.
