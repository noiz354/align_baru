Annotations

  • The reader is the product. reader-behavior.md defines three modes (vertical, single, double), two directions, four breakpoint layouts, a keyboard map, a two-representation page indicator, and a completion state. This page shows the structure of all of it; tier 4 makes it work.
  • Direction is not a mirror. Per §4, direction decides which physical page is logical page 1, which key means next, which swipe means next, which tap zone means next, and how a spread pairs. The three-zone row below is drawn once, and the mapping table says which zone means next in each direction — in RTL it is physically the opposite third.
  • displayIndex vs pageNumber. §4 calls this the single largest source of reader bugs. The indicator is written as displayIndex, computed as displayIndex = rtl ? M − pageNumber + 1 : pageNumber. With M = 240 and pageNumber = 229 in RTL, the indicator reads Page 12 of 240 — the reading-order position, not the physical page.
  • Chrome placement changes with width (§2): a bottom bar under 640px, a right rail 640–1023px, and a right rail plus top bar at 1024px and up. All three are drawn as separate frames because the structural difference is the point.
  • Zoom is a transform. §8.1: zoom 100–400% pans within the page box, never changes the logical page, and resets on chapter change and on entering or leaving double mode (§11).
  • Page slots persist. §3 and §15: out-of-window pages are placeholder elements with reserved dimensions, so the column height never changes and there is no layout shift.
  • Every key has a button. §9: the key map is an enhancement over visible chrome controls, never a replacement for them (NFR-A11Y-002/006).
