# Module boundaries

Feature modules expose DTOs, application service interfaces and domain types. They do not import Next route internals or infrastructure clients. `auth` supplies identity/session abstractions; `catalog` composes public queries across manga/chapter; `manga` owns work metadata; `chapters` owns ordering and page descriptors; `reader` consumes chapter manifest and progress port; `progress` owns progress/history; `library` owns collection/bookmark/preferences; `search` depends on catalog contracts and a search port; `admin` orchestrates authorized manga/chapter/upload commands; `uploads` owns staged workflow contracts; `media` owns opaque asset and delivery policy; `observability` only cross-cutting telemetry.

Allowed dependencies: reader→chapters contracts, progress; catalog→manga, chapters read contracts; search→catalog/manga read contracts; library→manga/chapter IDs, progress; admin→manga, chapters, uploads contracts, auth policy; uploads→media port, auth; server/db implements repository ports; server/storage implements storage/media ports; server/auth implements auth port; shared/contracts imports only shared/types and validation. No feature-to-feature implementation imports; dependency inversion via stable contracts prevents cycles. `shared/ui` is presentation-only and cannot import server modules.
