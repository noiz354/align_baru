# Test strategy (specification only)

No business logic tests are implemented in this phase. Future test layers: pure unit for page boundary/window calculations and schemas; integration against disposable PostgreSQL/object-store-compatible isolated test service; contract tests for DTO/errors; browser E2E via Playwright; accessibility automated + manual; security abuse and load/chaos exercises.

Planned cases: UNIT-READER-031 bounded page window; -032 reject negative/out-of-range; -033 first/last page; -034 RTL/LTR spread pairing and cover; -035 rapid direction/mode change. Integration: progress owner isolation, concurrent tabs/version conflict, deletion/unpublish; catalog visibility and stable cursor; session revoke/role matrix; archive traversal, symlink, bombs, MIME spoof, excess count/size/dimensions, checksum; upload quarantine/publication atomicity; storage delivery expiry. E2E: guest browse/detail/read; keyboard/touch navigation; mode/direction; failed image retry/offline transition; sign in → library → progress restore; editor draft → upload status → publish authorized content; unauthorized admin denied. Also DB constraints, migrations when authorized, metadata validation, rate limiting, API schema drift, WCAG manual and automated.

Tests must not rely on hardcoded pretend product services in production modules. Test fixtures are isolated under tests and clearly identified; no fixture becomes runtime default. E2E and integration require test-only environment safeguards. CI gates: format/lint, strict typecheck, focused tests, integration when touched, E2E on milestone/critical path, dependency/security scanning and bundle budgets.
